04. Saves you can retry. Data you own.

Before

  • A lost response followed by retry could save another plan.
  • No Clerk deletion receiver or application-data download.
  • Valid old tokens could recreate a manually deleted local user.

After

  • Owner/input-scoped keys return the same saved result on retry.
  • Verified deletion, atomic cascade and stale-session tombstones.
  • Authenticated JSON export with consistent user/workout data.

The external Clerk webhook subscription still needs a public endpoint and signing secret. Local tests verify the actual signature, proxy and database flow; they do not claim that provider delivery is configured.

06. One full-stack browser harness.

Disposable Postgres, ephemeral signed identities, real Go handlers and JWT verification, and the production Bun proxy. Only the external Clerk UI is substituted in the explicit test build. Release bundles are checked for fixture leakage.

Before

  • Separate Python HTTP smoke orchestration.
  • Mocked mutation and serialized-markup assertions.
  • Process health without schema readiness.

After

  • 26 applicable browser checks across desktop and mobile.
  • 411 lines removed across three replaced test files.
  • SQL, JWT, algorithm and cache invariants stay focused.
  • Readiness, release metadata, import checks and CI artifacts.

Total code grew because this pass adds lifecycle features, explicit contracts, the gallery and broader tests. Four duplicate mobile cases are skipped: three viewport-independent HTTP contracts and desktop PDF generation. No real Clerk provider flow or public deployment is claimed.
